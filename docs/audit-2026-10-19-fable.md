## Verdict

The entry is submittable: no key, token or Qloo response data is in the repository or its history, every call goes through `qloo exec`, only cultural entities and place names reach Qloo, the licence is MIT and the README, Devpost text and UI copy stay inside the four allowed claims. Three things should change before submitting, because they sit on the examples judges open first: the lead dog's places and map are driven by two cat shows (A1), the Park Slope litter is named after *My Cat from Hell* with the hook "a cat in My Cat from Hell" and no code screens a title's own name (A2), and the judged demo still runs on the free coding-plan model that milestone 5 said would be replaced (A3). After those, the two changes that would most raise the score are making the agent's own search step visible on saved results (A7) and giving Devpost a first-screen image instead of the 1024×4685 full-page capture (A8).

### P1

**A1. The lead dog's places and map rest on two cat shows; species is not enforced anywhere in title selection.**
`app/agent/profile_agent.py:330-346` (`strong_titles`), `:499-516` (`evidence_order`), `:519-547` (`find_venues` takes the top three by evidence), `app/classify.py:73-81` (`bucket` keeps any title with pets ≥ 0.8, ignoring the `dogs`/`cats` answers it already has), `app/profile.py:203-208` (`PET_TAGS` includes `keyword:qloo:cats`). Live `/result?animal=dog-02&location=park-slope`: the Qloo strip reads "15 places near the shelter, ranked for fans of Nature Cat, My Cat from Hell and Bluey" and the map caption "Fans of Nature Cat and My Cat from Hell stand out…". Decision 1 keys profiles by species "since a dog show and a cat show reach different fans", but nothing in code prefers a species match: *Nature Cat* and *My Cat from Hell* rank 1st and 2nd in Qloo's ranking for Park Slope, so code sends them as the venue and map signals for a dog. A judge reading the lead example sees a dog's venues chosen for cat-show fans, which undercuts the per-species design on the one page they are sure to open. Fix: in `evidence_order` (or a `species_order` used by `find_venues` and the map), prefer titles whose verdict matches the species (`dogs ≥ 0.5` for a dog profile, `cats` for a cat) before falling back to the rest; tell the AI the same in the instructions; rebuild the Park Slope dog example (`scripts/precompute_examples.py --force` after deleting that profile) and re-pin its places. Size M.

**A2. The Park Slope litter is named after *My Cat from Hell*; no check screens a title's own name, so "hell" reaches the hook.**
`app/agent/checks.py:166-207` (`check_name` screens the name and the character only), `:248-268` (`check_title` screens real-people and identity only), `:529-541` (`check_hook` screens trait and claim words only), `app/agent/listing_agent.py:585-588` (the hook is built from Qloo's title by code). Live `/result?animal=kitten-01&location=park-slope`, the third example on the start page: name buttons Smokey, Misty, Ash, each with "Qloo: My Cat from Hell", and the hook "Named after Smokey, a cat in My Cat from Hell." *My Cat from Hell* is a reality series about cats with problem behaviour; AGENTS.md's screen is for villains, violent or tragic characters, aggression words and words that put an animal down, and an adoption listing that introduces a kitten through a "cat from hell" fails that rule in spirit on the first click. The title is also 1st in every pet-tag list Qloo returned (`docs/qloo-findings.md`, 18 October), so every cat profile will offer it again. Fix: in `check_title`, refuse a title whose name contains a `NAME_BLOCKLIST` or `UNFLATTERING` word or a short extra list (`hell`, `from hell`, `nightmare`, `worst`) for any name, and add the rule to the listing instructions; let `open_title` use it so `repeated_titles` does not steer the model back to it; rebuild the Park Slope litter. Size S plus one rebuild (the profile is cached; four listing runs on the model, at most two `describe` calls each).

**A3. The judged demo runs on the free coding-plan model that milestone 5 said would be replaced.**
`README.md:144` ("the demo runs a free model through OpenCode Go") and `:174` ("The demo model is a free one"); `docs/decisions.md` #6 ("the judged demo runs on a paid model, as planned"); AGENTS.md milestone 5 ("switch to the paid model"). ### P2

**A4. Visitors' photos can fill memory: up to 500 sessions × 3 photos × 3 MB, and `POST /animals` has no allowance.**
`app/session.py:24-26` (`MAX_SESSIONS = 500`, `MAX_ANIMALS = 3`, `MAX_PHOTO_BYTES = 3 MB`), `app/main.py:632-704` (no per-visitor limit; each cookieless request makes a new session), `deploy/compose.yml` (no memory limit). **A5. `RUNS` is never pruned, and a run over a saved result is uncharged.**
`app/runs.py:56`, `:130-139` (`_new_run` always inserts), `:142-146` (`_saved` runs are free), `app/main.py:440-463`. Every `POST /runs` for `dog-02`/`park-slope` adds a `Run` with its `StepLog` for the life of the process, with no limit. Fix: keep `RUNS` as an `OrderedDict` capped at a few hundred, dropping finished runs first, and expire finished runs after an hour (`find_run`'s "runs are kept until the server restarts" would change to "for an hour"). Size S.

**A6. No timeout on the model client: a hung endpoint holds a run for up to 30 minutes.**
`app/agent/model.py:28-35` (`AsyncOpenAI` with no `timeout` or `max_retries`: the SDK defaults are 600 s and 2 retries), `app/agent/pipeline.py:50-51` (`UsageLimits` count requests, not time). The fallback chain is correct (`ModelAPIError` is an `AgentRunError`, so connection failures do fall to the fixed lookup and the template), but a stalled stream is not a failure, and the Working page's busy counter would just climb. Fix: `AsyncOpenAI(timeout=httpx.Timeout(60.0, connect=10.0), max_retries=1)` and `asyncio.wait_for` around each `agent.run` (about 240 s for the profile, 120 s for the listing) with `TimeoutError` added to `AGENT_FAILURES`. Size S.

- **Secrets and data.** `git ls-files` holds no `.env`, database or `var/` content; `.gitignore` and `.dockerignore` exclude them. A scan of the whole history for `*_API_KEY=`, `api_key`, `Bearer`, `sk-`-style tokens found nothing; the only real-looking UUID ever committed is inside a cited Daily Gazette URL in the evidence review. - **What leaves the app.** Qloo gets entity names and IDs, tag IDs, category tags and place names (`venue_input`, `pet_lists`, `find_local_titles`, `heatmap`, `tastes`, `check_location`); a typed area is refused if it holds a digit; the map pin never leaves the session. No name, email or identifier anywhere.
- **No direct Qloo HTTP.** Only `qloo exec` as a subprocess (`app/qloo/exec.py:123`); `urllib` is used for Photon and TypeSafe only, to hosts from settings (`https://` enforced for the classifier).
- **Claims.** README, Devpost, UI copy and the start page's intro: no "faster", "saves lives", "saves money" or "matches"; "accurate", "screens", "experiment" used; wording is "people in this area tend to like"; the baseline and name screens refuse identity-coded titles and names; the comparison shows are named only in the Why panel.
- **Devpost requirements.** MIT in `LICENSE` and `pyproject.toml` (verify the About section shows it on GitHub); public repo; demo live and fast (examples in about 0.1 s); English description ready to paste; the tagline is 179 characters.
- **Envelope statuses and retries.** All six statuses handled in `envelope.py`, `exec.py`, `_Builder.call`, `qloo_call`, `list_failure`, `rank_titles`, `find_venues`, `heatmap`, `tastes` and `check_location`; retries only when `retryable`, with the rank exception documented; `needs_input` is cached and shown as candidates or chosen with a stated reason, never forced; partial and degraded lists are not used for the baseline or ranking.
- **Subprocess failures.** Timeout (90 s), `OSError`, bad JSON and exit codes 1, 2 and 4 all raise `QlooExecError`, which every caller turns into a note or "unavailable".
- **Limits and caps.** Per-visitor per hour in memory with sweeping; daily caps in SQLite; charged before work, refunded when no live call; `LimitReached` is a 429 notice; places have their own allowances and a concurrency cap.
- **Degraded modes.** Model down or refusing: `ModelAPIError` is an `AgentRunError`, so the profile falls to the seed lookup and the listing to the template, both saying why. Qloo key dead: error envelopes become "unavailable", pages read the cache only, examples unaffected, typed areas get a 503 message. Classifier down: one timeout, then saved answers only. Photon down: the field works as typed, pins are retried on a later save. Cold cache: the start page hides the examples band, pages show "No venues for this area yet" and the template, nothing crashes.
- **SSE and concurrency.** Snapshot-then-queue under a lock, the error logged before `done`, a regression test for it; one profile build per location and species per loop; one listing per shelter; one writer of a profile's points; live slots reserved with `BEGIN IMMEDIATE` across processes.
- **Input validation.** Typed area: letters only, 2–80, no digits; refine 3–200; approve text 1–3000, variant must exist, local name must be an option, the generic name is re-checked, cautions must survive the edit; add-animal fields ≤ 120, ≤ 6 facts, species, sex and the five answers as enums, photo by magic bytes, ≤ 3 MB, `Content-Length` required for multipart, spool kept in memory; places `q` ≤ 200 and coordinates bounded; pin coordinates bounded and rounded.
- **XSS and redirects.** Starlette's Jinja environment autoescapes; no `|safe` anywhere; page data goes through `tojson` inside `application/json` script tags; the skin's scripts write `textContent` or DOM nodes (the one `innerHTML` is a clear); Leaflet tooltips receive Qloo titles as strings, which are not visitor input, and the area regex excludes `<` and `>`. Every redirect is app-relative with a fixed prefix; `ui` is validated against the folders.
- **SSRF.** Geocoder, classifier and tile hosts come from settings only; the browser only ever fetches the app's `/api/`, which the contract test enforces.
